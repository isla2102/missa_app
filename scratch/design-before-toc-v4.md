# MISSA 제품 및 데이터 설계

기준: Handoff v0.3 및 2026-10-18 사용자 답변. 이 문서는 제품 결정 기록이며 4단계 시각 토큰·컴포넌트 확정을 뜻하지 않습니다. Windows에서 design.md와 DESIGN.md는 같은 파일이므로 이후 디자인 시스템을 이 문서에 누적합니다.

## 목적과 범위
한국어 예비신자·일반 신자의 개인용 로컬 MVP. 태블릿 가로의 연속 본문 두 페이지 리더, 오른쪽 오버레이 Drawer, 저장된 콘텐츠의 오프라인 열람을 목표로 합니다. 좌우 페이지가 본문/해설 전용으로 나뉘는 구조는 아닙니다. 서버·계정은 필수가 아닙니다.

## 본당과 회차 — 사용자 결정
- 본당 실제 이름은 미설정이며 표시명은 ‘내 본당’ 하나입니다. 가상 방문 본당은 제거 대상입니다.
- 회차 표시명: 새벽미사, 교중미사, 주일 저녁 젊은이 미사. 젊은이 미사는 일요일 저녁입니다.
- 실제 시간·성가 번호는 미확인입니다. 임의로 채우지 않고 null 또는 미입력으로 관리합니다.
- 세 회차는 같은 전례일·순서·통상문·고유문·독서·복음·안내 규칙을 공유합니다. 차이는 네 역할의 성가 배정뿐입니다.

## 데이터 관계
`LiturgicalDay → MassDocument(공통) → 회차별 HymnSet`

같은 주일의 세 회차는 동일한 MassDocument를 참조합니다. 회차에 전례 본문을 복제하거나 회차별 전례 override를 두지 않습니다. 본당·회차 식별자는 성가 조회 범위이며 전례 날짜 계산 입력이 아닙니다.

성가 역할은 entrance, offertory, communion, recessional입니다. 번호·제목·직접 입력한 가사/메모·출처 URL을 회차별로 관리합니다. 기존 missa-v02-hymn 저장 키의 호환·마이그레이션은 구현 전에 정의하고 기존 데이터를 임의 삭제하지 않습니다.

## 정보 구조 방향 — 사용자 답변 반영, 검토 HTML 승인 대기
- 상단: 날짜·회차·사용자 모드, 우측 상단 성가·주요 기도문. 본당은 ‘내 본당’ 단일 문맥으로 표시합니다.
- 본문: 현재 예식 한 파트의 연속 본문을 두 페이지로 펼치는 리더. 파트 내부 페이지 넘김과 예식 간 이동을 분리합니다.
- 오른쪽 Drawer: 목차, 성가, 주요 기도문, 보기 설정, 안내.
- 보기 설정: 우측 하단, 글자 크기·배경 테마 등 표시 설정. 안내는 바로 오른쪽에 둡니다.
- 안내: 전례 시나리오 선택을 ‘개발용 예시’로 구분. 자동 판별처럼 표시하지 않습니다.
- 시나리오와 회차는 독립적입니다. 회차 선택으로 전례일·시나리오를 변경하지 않습니다. 개발용 평일 예시와 주일 회차의 충돌 표시 정책은 검토 HTML에서 제안합니다.

## 모드와 읽기 상태
예비신자 모드는 행동 안내·응답 강조·용어 설명·영성체 안내를 표시합니다. 일반 모드는 같은 공식 전례 본문에서 보조 설명을 최소화합니다.

모드·회차 변경 시 읽기 위치를 유지합니다. 회차 전환은 성가 표시만 갱신합니다. Drawer를 닫으면 읽기 위치와 적절한 키보드 초점을 복원합니다. 재조판·북마크 위치는 페이지 번호만이 아니라 sectionId, paragraphId, offset 등 안정적인 콘텐츠 식별자로 관리합니다.

## 기술과 콘텐츠
Flutter·SQLite·JSON은 권장 아키텍처이며 현재 구현된 앱 스택은 아닙니다. 수집·정규화 도구로 Python 등을 검토합니다. 전례 구성·모드 표시·성가 편성을 분리합니다.

선택 예식은 임의 확정하지 않으며 미지원 특별 전례를 일반 미사로 표시하지 않습니다. 공식 원문을 AI가 추측 생성하지 않습니다. 연동 시 출처 URL·취득 시각·이용 조건·검증 상태를 기록합니다. 공식 API·이용 조건 검토와 자동 수집은 미완료입니다.

## 구현 상태와 검증 목표
원본 v0.2는 공통 전례 샘플·회차별 성가 저장을 포함합니다. 설정·북마크·안정적인 읽기 위치 저장은 미구현입니다. 회차 변경 시 성가 패널 닫힘, 영성체 성가 링크 누락, textarea 화살표 처리, 모바일 페이지 누락은 수정 대상입니다.

검증 목표: 세 회차 전례일·본문·순서 동일성, 네 성가 역할의 독립 저장, 모드·위치 유지, Drawer·키보드 동작, 새로고침 복원, 좁은 화면의 모든 본문 접근. 실제 JSON Schema에는 유효·무효 사례 및 교차 참조 검증을 마련합니다. 현재는 정적 확인만 수행했으며 기능 검사 통과를 주장하지 않습니다.


## 2026-10-18 리더 수정 — 사용자 정정 반영, 검토 v2
- 두 페이지는 현재 예식 한 파트의 연속 본문이다. 서로 다른 예식을 좌우에 배치하지 않는다.
- 현재 예식이 두 쪽보다 길면 같은 예식 안에서 페이지를 넘긴다. 본문 세로 스크롤에 의존하지 않는 실제 조판은 후속 구현 대상이다.
- 하단 순서 이동에는 이전·다음 예식 이름을 표시한다. 펼침 번호를 주요 네비게이션으로 사용하지 않는다.
- 성가·주요 기도문은 우측 상단. 보기 설정은 우측 하단, 안내는 보기 설정 바로 오른쪽.
- 목차는 우측 Drawer로 제안하며 상시 고정은 대안으로 남긴다.
- review/02-ia-v2.html 작성. v1 보존. 이번 체험의 페이지 분리는 수동 구조 예시이며 실제 자동 조판·테마·글자 크기 적용은 미구현이다.
- 단계 승인 대기. 검토 화면 조작을 승인으로 기록하지 않는다.
